# 沉浸式动漫叙事首页改造方案

## 1. 概要（Summary）

在不改变 Firefly 6.9.4 现有架构、不引入新依赖的前提下，把首页 `/`（`[...page].astro` 的第 1 页）从「全屏壁纸 + 滚动后露出文章列表」改造为一个五章式的**可滚动动漫叙事长页**：

- 第 1 章 春日序幕（全屏动漫场景 + 电影式镜头推进 + 标题/简介时序出现 + 继续探索提示）
- 第 2 章 窗边日常（真实个人资料：昵称 / 简介 / 头像 / 社交链接，非卡片式空间构图）
- 第 3 章 记忆与记录（真实文章 3–5 篇，杂志式错位排版，进入原文详情页）
- 第 4 章 黄昏与兴趣（真实分类/标签 + 相册/番组等真实入口，无真实数据则不渲染）
- 第 5 章 星空与结束（夜景收尾 + 导航 / 社交 / 回顶部 + 复用真实 Footer）

**严格保留**：分页路由（`/page/2/` 及以后仍是原列表页）、文章详情/分类/标签/归档/搜索/相册/番组页面、Swup 页面切换、主题模式、图片灯箱、SEO、响应式、原有侧边栏/评论等全局功能。

**动画方案**：优先复用项目现有能力（原生 CSS 动画 + `IntersectionObserver` + `requestAnimationFrame` 滚动视差），**不引入 GSAP 或任何新依赖**（符合用户「宁可功能少，也不要堆砌功能」的偏好）。动画脚本遵循项目已有的 Swup 事件约定，并做幂等初始化与销毁。

## 1.5 实施约束与优先级（Implementation Constraints）

本方案是**实施目标与设计约束**，不代表所有实现细节都已经过验证。**以当前仓库实际源码为最终依据。**

**开发前先做一次「源码核对」（read-only）**：重新确认首页路由分流点、`Layout.astro` 首页规则族、`MainGridLayout.astro` 的 Swup 容器约束、`@swup/astro` 的钩子/容器配置、以及各 config 对象的实际字段。若方案中的路径、字段名、生命周期事件或 DOM 结构与源码不一致，**先采用符合现有架构的实现，不得为了匹配方案而破坏现有功能**，并在交付说明中记录偏差。

**额外硬约束**
- 不新增依赖。
- 不重写博客架构。
- 不修改任何文章内容。
- 不破坏分页、文章详情、搜索、主题切换、Swup、Footer。
- 不删除方案之外的现有功能。
- 不把未经验证的构建结果 / 浏览器测试 / 路由检查描述为「已通过」；无法完成的验证要列明原因与剩余风险。

**优先级（冲突时按此裁决）**
1. 现有功能正确性
2. 页面可用性与性能
3. 动画完整度
4. 装饰性效果

**开发顺序（严格按阶段推进，每阶段结束执行适用的检查）**
1. **路由分流 + 五章静态结构**：先让 `/`（第 1 页）渲染新首页、第 2 页起保持原列表与分页，五章内容以静态、可读、可点的方式落地（先不做动画）。
2. **用现有本地图片完成视觉布局**：本阶段**只使用仓库已有素材**（`src/assets/images/**` 现有壁纸等），把五章构图、层级、满宽满高、响应式跑通。
3. **滚动动画 + 动画生命周期 + 无障碍降级**：实现视差/分镜/分段揭示、`prefers-reduced-motion` 降级、Swup 幂等初始化与销毁、无 JS 可读。
4. **新插画 + 视觉细节 + 性能优化**：此时才处理新插画（生成或替换素材）、光影/色调过渡细节、图片加载策略与滚动性能。
5. **收尾校验**：运行仓库中**真实存在**的构建/检查命令（见 `package.json`），核对路由与回归，如实报告结果。

## 3. 变更方案（Proposed Changes）

### 3.1 新增 `src/config/homeConfig.ts` —— 首页文案与图片的可编辑集中点

**为什么**：用户要求「如果现有资料不足，可以使用简洁的占位文案，并将其集中放在容易修改的位置」，并要求图片路径清晰可替换。

**内容**（导出 `cinematicHomeConfig`，便于用户单独替换文案/图片，不改组件）：

- `chapters.spring`：`eyebrow`、`intro`（第 1 章短句）、`scrollHint`（如「继续探索」）、`skipLabel`（「跳过序幕」）
- `chapters.window`：`eyebrow`、`lines: string[]`（第 2 章逐句简介；**默认留空 → 组件回退使用 `profileConfig.bio` 等真实资料**）
- `chapters.memory`：`eyebrow`、`title`、`moreLabel`（「浏览全部文章」）、`archiveUrl: "/archive/"`
- `chapters.dusk`：`eyebrow`、`title`、`description`
- `chapters.night`：`eyebrow`、`title`、`closing`、`backToTopLabel`
- `images`：`springFar`、`springNear`、`window`、`memory`、`dusk`、`night`（默认指向 `public/assets/images/home/*`，注释标明「替换此处的图片路径即可换正式素材」）
- `postsCount: 5`（第 3 章展示篇数，实际按文章总量自动收敛到 3–5）
- `interestsNav: string[]`（留空时组件自动读取真实启用的页面路由）

同时在 `src/config/index.ts` 增加 `export { cinematicHomeConfig } from "./homeConfig";`（与现有导出风格一致，不改 `types/config.ts` 以减少改动面）。

### 3.2 首页插画素材 `public/assets/images/home/`（**放在第 4 阶段执行**）

**阶段 2 先用仓库现有素材**：`homeConfig.images` 先指向现有壁纸（`src/assets/images/DesktopWallpaper/` 下的 `d3.avif`、`d5.avif`、`d1.avif`、`d17.jpg`、`d19.jpg`、`d18.png` 等），把布局/层级/响应式跑通，**不阻塞前 3 个阶段**。

**阶段 4 再替换为正式插画**：用 `GenerateImage` 生成 6 张**本地**动漫插画（横构图 16:9），写入 `public/assets/images/home/`：
`spring-far.jpg`、`spring-near.jpg`（第 1 章远景/近景分层，用于视差）、`window.jpg`（第 2 章）、`memory-dusk.jpg`（第 3 章）、`sunset.jpg`（第 4 章）、`night.jpg`（第 5 章）。

- 生成提示词围绕：日系动漫插画、新海诚式光影氛围（仅作艺术方向）、樱花/微风/窗边/黄昏/星空/远处城市灯光；**不含**任何科技/终端/霓虹元素。
- 落盘为本地静态资源（`public/` 下不被 Astro 构建优化，路径稳定、便于用户替换）；组件内用 `<img>` 精确控制 `loading/decoding/object-fit/object-position`，并写清 `alt`。
- **若生成不可用**：保留「现有素材」方案，并在交付说明中**明确标注哪些仍是回退素材**。
- 加载策略：仅第 1 章 `loading="eager" fetchpriority="high"`，其余 `loading="lazy" decoding="async"`。
- 图片路径全部集中在 `homeConfig.images`，组件内不硬编码（便于替换）。

### 3.3 新增 `src/components/layout/CinematicHome.astro` —— 首页主体（唯一新增组件）

一个全宽、满高、可正常滚动的长页，内部为 5 个 `<section>`。**不使用**玻璃拟态、圆角卡片堆叠、渐变文字、发光边框、网格/HUD；不使用 Emoji 充当视觉。

**Props**：`posts: CollectionEntry<"posts">[]`（第 1 页真实文章，取前 `postsCount` 篇，自动收敛 3–5；不足 3 篇时按实际数量渲染）。

**服务端数据**（组件 frontmatter，全部为真实数据，不做虚构）：
- `siteConfig.title / subtitle`、`profileConfig.name / bio / avatar / links`（第 1、2、5 章）
- `page.data` 传入的文章（第 3 章）：`title / published / category / tags / image / description` + `getPostUrlBySlug(entry.id)` + `getCategoryUrl(category)`
- `getCategoryList()`（第 4 章「兴趣坐标」，真实分类 + 计数 + 真实链接）
- `galleryConfig.albums`（`length>0` 才渲染相册模块，否则**不渲染**）、`siteConfig.pages.gallery/bangumi/friends`（决定入口显隐）
- `navBarConfig.links`（第 5 章导航捷径）

**第 1 章 春日序幕**
- 三层结构：`far`（天空/远景，视差系数最小）+ `mid`（场景主体，做镜头推进 `scale 1.12→1`）+ `near`（前景花瓣/枝叶，视差系数最大）。
- 开场：初始化时给根元素加 `.is-entering`，由 CSS 过渡完成 ~2.0–2.4s 的景深推进 + 亮度变化；`prefers-reduced-motion` 时直接呈现（无位移/无缩放）。
- 文案时序：`ysdy` 主标题（逐字/分行 `translateY+opacity`，错峰 delay）→ `ysdy's Blog` 副标题 → `intro` 短句 → 「继续探索」提示；各自独立 delay，**非同步**。
- 花瓣：少量 CSS-only 漂浮花瓣（移动端与 reduced-motion 下关闭）。
- 顶部渐隐遮罩保证导航可读性（不压暗主体）。
- 滚动提示：`role="button"`、`tabindex="0"`、`aria-label`，点击/Enter/Space → `scrollTo` 第 2 章；提供「跳过序幕」按钮 → 直接跳第 2 章。**不锁滚动、不强制观看**（无 `overflow:hidden`，无定时锁）。

**第 2 章 窗边日常**
- 背景 `window.jpg` 视差（较慢）；前景窗框/桌面剪影层（较快）。
- 文字以空间构图分散在画面不同位置（桌面端绝对定位 + 大留白；移动端回退为纵向堆叠），逐句 IntersectionObserver 触发进入。
- 真实内容：昵称、`bio`（或 `chapters.window.lines`）、头像、社交链接（`profileConfig.links`，含 `showName` 处理）。

**第 3 章 记忆与记录**
- 回忆氛围背景（`memory-dusk.jpg`，低沉、克制）。
- 杂志式错位排版：图片块与文字块左右交替、上下错位；**不使用**统一规格卡片网格。
- 每篇：真实封面（`ImageWrapper` 或 `<img>`，`image` 为空时使用统一精致视觉方案——根据分类生成的低饱和色块 + 图标 + 分类名，非随机图）；真实标题、日期（`formatDateToYYYYMMDD`）、分类（真实链接）、标签；整块链接到 `getPostUrlBySlug(entry.id)`。
- 图片与文字的进入节奏不同（图片 `scale+clip` 缓入，文字 `translateY` + 延迟）。
- 「浏览全部文章」→ `/archive/`（真实存在的归档页）。

**第 4 章 黄昏与兴趣**
- 温暖黄昏渐变背景 + 大留白；横向编排（移动端纵向）。
- 「兴趣坐标」：`getCategoryList()` 真实分类（名称 + 计数）→ 真实分类页链接。
- 条件模块：`galleryConfig.albums.length > 0` 时渲染相册封面视差行；否则**不渲染**（不伪造数据）。番组入口仅在 `pages.bangumi` 为 true 时显示（只给入口，不在首页抓取番组数据，避免构建期外部依赖）。
- 入口行：`/gallery/`、`/bangumi/`、`/archive/`、`/friends/`（按 `siteConfig.pages.*` 显隐）。

**第 5 章 星空与结束**
- 夜色背景 `night.jpg` + 克制的 CSS 星光层 + 远处城市灯光渐变；顶部与第 4 章的黄昏做衔接渐变。
- 内容：导航捷径（`navBarConfig.links`）、社交链接（`profileConfig.links`）、回顶部入口（键盘可达，带 `aria-label`）。
- 全局 `<Footer>`（版权 / 建站计时 / RSS / Sitemap / `FooterConfig.html` 备案位）保留，并通过 CSS 让其在首页延续夜色带，**不删除、不重复造一份**。

**响应式 / 无障碍 / 性能**
- `prefers-reduced-motion: reduce`：关闭视差与持续漂浮动画，改为直接呈现（用 CSS media query + JS 判据双保险）。
- 移动端（<768px）：视差系数降为 0 或极小、关闭花瓣漂浮、章节改为自然纵向阅读。
- 所有图片含 `alt`；文字与背景对比度经遮罩/渐隐保障；不产生布局偏移（预留 `aspect-ratio` 或固定高度）。
- **JS 不可用或脚本初始化失败时**：章节内容默认可见可读（渐进增强：把「隐藏态」交给 `html.js-cinematic`（由脚本自身立即添加）后的类，保证无 JS 时全部可见）。

**组件内脚本（Astro 打包 `<script>`，幂等 + 可清理）**
- `init()`：仅当 `#cinematic-home` 存在时执行；若已有实例先 `destroy()`；建立 `IntersectionObserver`（`data-reveal` → `.is-visible`，经 `--reveal-delay` 错峰）、滚动视差 `rAF` 循环（读 `data-parallax`/`data-speed`）、点击/键盘滚动向、`resize` 节流。
- `destroy()`：`disconnect()` 观察器、取消 `rAF`、移除 `scroll/resize/keydown` 监听。视差循环内每帧检查 `root.isConnected`，DOM 被 Swup 替换后自动停止。
- 触发时机（沿用项目既有约定）：脚本末尾立即 `init()`；监听 `document.addEventListener("astro:page-load", init)`、`"astro:after-swap", init`；`window.swup?.hooks?.on("content:replace", init)` 与 `("visit:start", destroy)`（存在时才绑定）。避免重复注册导致监听器泄漏。

### 3.4 修改 `src/pages/[...page].astro` —— 首页与分页分流（**保护路由的关键**）

- 新增 `import CinematicHome from "@/components/layout/CinematicHome.astro";`
- 在模板中：
  - `page.currentPage === 1` → 渲染 `<CinematicHome posts={page.data} />`（**不渲染 `Pagination`**）。
  - 否则 → 保持现状：`<PostPage page={page} />` + 原 `Pagination`（`page.total > page.size` 时）。
- `getStaticPaths` **完全不动**，因此 `/`、`/page/2`、`/page/3` … 的静态路由、分页数量、URL 结构均不变；第 2 页起仍是原列表页。
- 页面底部原有的「响应式分页设备类」`<script>` 保留（对首页无害）。

### 3.5 修改 `src/layouts/Layout.astro` —— 首页画布改为可滚动的满宽画布

## 4. 假设与决策（Assumptions & Decisions）

1. **不引入 GSAP / 新依赖**：项目已有「原生 CSS + IntersectionObserver + rAF」模式，足以实现分层视差、镜头推进与分段揭示；引入第三方库会与 Swup 生命周期叠加复杂度且违背用户偏好。若后续需要更复杂的滚动编排，再评估 GSAP+ScrollTrigger（本方案不涉及）。
2. **首页第 1 页彻底改为叙事页**，不保留旧 banner 首页样式（用户要求「把现有首页重新设计」）。因此直接改写 Layout 内首页规则族，而非叠加 `!important` 覆盖。
3. **第 4 章只用真实数据**：相册配置为空 → 不渲染相册模块；番组不在首页发请求，仅提供入口；改用真实分类/标签作为「兴趣坐标」。
4. **图片分两步走**：阶段 2 先用仓库现有壁纸素材把布局跑通（不阻塞结构与动画）；阶段 4 再用 `GenerateImage` 生成 `public/assets/images/home/` 的正式插画并替换路径。新插画落入 `public/`（不被构建优化、路径稳定、易替换）；若生成不可用则保留现有素材方案，并在交付说明中明确标注哪些仍为回退素材。
5. **`body.homepage` 已足以表达「新手首页」**，故不新增 body class（避免与 `Layout.astro` 中 Swup `visit:start` 对 `homepage` 类的切换逻辑产生分叉）。
6. **第 5 章复用全局 `<Footer>`**，不重写一份页脚（避免版权/备案/RSS 信息重复与漂移）。
7. 动画的「隐藏初始态」由脚本自加类触发，保证**无 JS 时内容仍可读**（渐进增强）。
8. 分页判断依据 `page.currentPage === 1`，不改 `getStaticPaths`，路由零风险。
